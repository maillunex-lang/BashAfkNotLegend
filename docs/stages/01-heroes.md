# Этап 01 — Герои и коллекция

Статус ROAD: `NOT_STARTED`  
Зависит от: 00 (контракты + ответы на BQ, минимум BQ-01/04 для полноценных клиентов)

## Цель

Серверная модель героев/фракций/классов/инвентаря/рангов/резонанса/экипировки; минимальный каталог; отображение одного и того же героя на обоих клиентах.

## Утверждённые требования (GAME.md)

- HERO-001 C … HERO-004 B, AFK-002 C, AFK-003 C, AFK-004 C (постепенное открытие)
- TECH-001 B, TECH-002 A, TECH-005 B

Ссылки: [GAME.md](../../GAME.md) §2 этап 03/05, [CONTENT_SCHEMA.md](../../CONTENT_SCHEMA.md)

## Зависимости

- JSON Schema / OpenAPI каркас
- Auth (BQ-01) для привязки коллекции к аккаунту
- Локаль строк (BQ-04) — допускается hardcode RU до ответа

## UX

1. Коллекция: список героев, фильтр фракция/класс.
2. Карточка: портрет, статы, навыки, цитаты.
3. Отряд: 5 слотов, визуально 2 front / 3 back.
4. Экипировка 6 слотов; ранг/осколки.
5. Резонанс: 5 основных + sync-слоты.

## Модель данных

См. CONTENT_SCHEMA: catalog hero, instance, equipment, resonance.  
Таблицы (черновик): `heroes_owned`, `inventory_items`, `equipment`, `resonance_slots`, `roster`.

## API / события

`/v1/heroes`, `/roster`, `/inventory`, `/resonance`, rank-up, equip — [API_CONTRACT.md](../../API_CONTRACT.md) §4.

## Безопасность

Сервер валидирует все апгрейды; клиент не доверяется; идемпотентность мутаций.

## Edge cases

- Дубликат rank-up request
- Экип занят другим героем
- Резонанс-цикл
- Неизвестный hero_id / asset

## Производительность

Каталог кэшируется по content_version; коллекция игрока — пагинация при росте.
